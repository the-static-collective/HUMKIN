# Radio House 001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a durable, source-grounded architecture and branch/status evidence spine without changing HUMKIN broadcast behavior.

**Architecture:** Keep current runtime in place. New proposal-only schemas and a deterministic Python generator operate over repository files and GitHub metadata, emitting two Markdown reports. Integrate report generation with the existing GHoT garden pulse, not a competing database.

**Tech Stack:** GitHub Actions, Python 3.11 standard library, JSON Schema documents, Markdown.

**Spec:** `docs/superpowers/specs/2026-11-21-radio-house-001-design.md`

## Global Constraints
- Preserve public listener fallback and all existing URLs.
- No cloud/broadcast/Supabase/R2 writes; no new credentials.
- Never infer on-air or real-device outcomes from GitHub PRs or code.
- Keep `CONTINUE.md` produced by GHoT and avoid conflicting writer workflows.
- On pagination/API failure, do not emit a partial inventory.

## Review Focus
- Malformed/stale GitHub snapshots must fail rather than silently claim completeness.
- Stacked PR bases differ from main; inventory must show them truthfully.
- Unexpected Markdown branch titles must not break generated tables.
- Unavailable device/deployment checks must remain UNKNOWN.
- A branch present with no PR must not be labeled merged or retired.
