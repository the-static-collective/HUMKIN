# Radio House 001 — approved additive design

## Intent
Consolidate HUMKIN's proliferating radio histories and implementation surfaces without disturbing the working signal, preserving experiments and improving cross-chat operational truth.

## Selected approach
A **contract-first modular monorepo** with additive documentation, machine-readable provisional contract schemas and an automatically refreshed source/branch evidence report. Alternatives rejected for this first slice: a destructive whole-repo restructure (breaks live routes/build roots) and immediate microservice/repository splitting (more operational authorities and deployment cost).

## Scope
Produce (1) authoritative ownership/architecture map, (2) generated, source-linked current-state report that never fabricates deployment or actual listening, (3) provisional recording/station/program/witness contracts, and (4) comprehensive observable branch inventory with selected investigation doors.

## Non-goals
No media writes, Cloudflare/Supabase mutation, site path changes, Android replacement, transmission change, branch merges, live worker deployment or public player cutover.

## Constraints
Preserve original user-approved fallback behavior and transmitted metadata truth. Never equate source, merge, deploy, HTTP response, schedule publication and sound heard. Do not make a second canonical catalog. New branch inventory may be incomplete if GitHub pagination or permissions fail; fail rather than silently show a partial census.

## Acceptance
Offline generator/tests fail closed for malformed snapshot; open PR relations and branch heads are attributable; deployment/field truth marked unverified; existing GHoT CONTINUE generation remains intact; artifacts can be safely inspected in a PR and regenerated without live actions.
