# NIGHT WATCH 001 — observed listening and a slower Outpost

Implemented in the browser/installed PWA surfaces `/fm/` and `/fm/orchard/`. This is **not an updated native Android APK**; native background playback remains a separate app task.

## Real observations, not a simulation

- The existing radio audio element and Orchard audio element report playback to the same local Night Watch journal, using their existing qualified `timeupdate` checks. No journal entry is created by loading the page, opening a report, letting an idle timer run, or keeping a screen unlocked.
- Only forward, bounded audio progress (greater than zero and no more than five seconds per callback) can be recorded. The model has no timer-based earning method. The underlying Orchard's local HUM/XP grants are unchanged, and Night Watch does **not** award any extra HUM.
- A song or station cart counts as **heard** only after at least 20 seconds of observed playback of that particular recording in a watch. "First logged here" means first qualified observation **since Night Watch was installed in this browser storage**, not an assertion that the human has never heard the recording elsewhere. Song and station-cart totals are kept distinct.
- Real Orchard discoveries and XP level changes appear only if the listener engine actually returns a discovery or the local level advances during observed playback. Nothing is generated by the report renderer.
- A watch ends after 30 minutes without observed audio. Finished watches can be opened later. If a watch continues overnight, its **in-progress** summary becomes visible after five logged minutes, so a listener returning to an ongoing radio can see what has actually been recorded without waiting for silence.
- Records are stored in `localStorage` on this origin, with bounded watch history and a bounded set of heard track IDs. They are not accounts, server-signed receipts, broadcast proofs, complete listening histories, or portable automatically between devices. Browser data removal or privacy modes can erase them.

## Quiet interface and staged doors

The radio landing page gains a small Night Watch ticket in its existing Orchard passage. The Orchard player gains the same ticket. The ticket does not expand by itself and does not interrupt playback. Both surfaces share the same report journal because they have the same origin.

The Orchard's introductory UI now opens three useful *doors* progressively: personal Signal at local level 3, Station Guilds at level 3, and the Living Orchard network at level 5. The substantial Guild and network invitation sections remain out of the first-screen path until those levels. Bootleg Frequency is listed as an unshipped later feature, not a working network tuner. **These are discovery/UI gates, not security gates:** direct URLs remain reachable and server permissions continue to govern real submissions/trades.

Existing full FM controls and homepage are preserved. Chart-qualified plays, server Guild credits, server collectibles, and local HUM remain separate ledgers.

## Android limitations and next layer

Browser playback may stop when Android suspends or kills a tab; Web MediaSession and preloading cannot guarantee next-track transitions while the app is backgrounded. No fake airtime is credited during a suspension. The existing `PHONE PLAYER PLAYLIST` provides a more reliable native-player route for screen-off listening but does not send native-player playback records back into Night Watch. Fully dependable background playback **with** Night Watch recording requires a native Android Media3 foreground playback service with user-visible notification, carefully scoped local history persistence, and a native journal integrated into the Android feature branch. That Android source lives on the unmerged `feat/native-android-radio-001` branch, not on `main`; companion PR #93 adds native Night Watch to that branch.

## Tests

`node --test tests/night-watch.test.cjs` checks that idle time earns no record, source events have bounded progress, songs require a 20-second threshold, repeated hearings are not relabeled first-time, quiet gaps close watches, actual discoveries and levels are preserved, and the radio/Orchard interfaces are wired to the same module. The site validation workflow includes the test. Service worker shell v46 includes both new scripts so installed browsers can load offline interface code (not automatically cache song audio).
